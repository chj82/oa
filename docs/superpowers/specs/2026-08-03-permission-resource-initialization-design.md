# 权限资源初始化设计

## 1. 背景与目标

当前初始化数据把分页、树、详情和关联 ID 查询分别定义成 `ACTION` 资源，导致角色即使拥有页面菜单，也可能因缺少页面基础查询接口而固定返回无权限；授权操作还可能因缺少弹窗依赖的查询接口形成不可工作的权限组合。

本次重新定义系统资源与接口关联，使每个可授权资源本身都是可工作的最小权限单元，并以一份适用于空库的完整初始化 SQL 作为精确配置真相源。

## 2. 范围

### 纳入范围

- 系统接口目录初始化。
- 系统管理目录及员工、部门、角色、资源、接口、任务管理资源初始化。
- 菜单、操作资源与接口的完整关联。
- 默认部门和默认超级管理员初始化。
- 初始化配置结构测试与文档约束。

### 不纳入范围

- 修改现有权限鉴权算法。
- 修改 Controller 接口路径或前端页面交互。
- 保留旧角色、旧授权关系或为已有数据库提供增量订正。
- 自动执行 SQL 或引入数据库迁移框架。

## 3. 权限资源语义

### 3.1 目录

`DIRECTORY` 只组织导航层级，不直接关联接口。

### 3.2 菜单

`MENU` 表示页面访问能力，必须关联页面首次打开和正常展示所必需的基础读取接口，例如分页、列表或树查询。获得菜单后，页面不能因为缺少独立的“分页权限”或“树权限”而固定加载失败。

菜单不自动获得新增、修改、删除、启停、授权等操作接口。

### 3.3 操作

`ACTION` 表示用户主动触发的独立操作。一个操作需要多个接口共同完成时，这些接口必须全部关联到同一个操作资源，不能再拆成需要分别授权的技术性资源。

例如：

- 员工分配角色同时依赖角色列表、员工当前角色和保存员工角色。
- 角色资源授权同时依赖资源树、角色当前资源和保存角色资源。
- 资源关联接口同时依赖接口列表、资源当前接口和保存资源接口。

详情查询只有在页面存在独立详情操作时才保留对应 `ACTION`；页面没有详情入口时，不创建无效的详情资源。

## 4. 系统页面划分

| 页面 | 菜单基础能力 | 独立操作 |
|---|---|---|
| 员工管理 | 员工分页 | 新增、修改、启停、删除、重置密码、分配角色 |
| 部门管理 | 部门树 | 新增、修改、启停、删除 |
| 角色管理 | 角色分页 | 新增、修改、启停、删除、资源授权 |
| 资源管理 | 资源树 | 新增、修改、启停、删除、关联接口 |
| 接口管理 | 接口分页 | 查看详情、启停 |
| 任务管理 | 任务列表 | 执行任务 |

分页、树、关联 ID 不再作为可单独授权的 `ACTION` 出现在授权树中。

## 5. 初始化策略

- 以空库为前提，依次执行 `backend/sql/schema.sql` 和 `backend/sql/data.sql`。
- `data.sql` 一次性维护默认部门、默认管理员、接口目录、资源树、资源接口关联和权限快照初始版本。
- 初始化 SQL 保持可重复执行，不重复新增部门、员工、接口、资源或关联。
- 初始化 SQL 不负责清理或迁移已有业务数据；需要重新初始化时由人工清空并按明确顺序执行。
- 任务管理并入完整初始化配置，不再依赖独立补丁形成最终权限模型。

## 6. 长期约束

- 新增页面菜单时，必须同时配置页面正常展示所需的基础读取接口。
- 新增操作资源时，必须配置完成该操作的全部接口依赖。
- 禁止为分页、树、关联 ID 等内部调用机械创建独立操作权限。
- 前端按钮资源编码与 `ACTION` 保持一致；菜单和操作的接口访问最终仍由资源接口关联鉴权。
- Controller 接口变化时必须同步更新完整接口目录及资源接口关联 SQL。

## 7. 验收标准

- 普通角色只授予某个菜单后，该页面可以正常打开并加载基础数据。
- 未授予操作资源时，对应按钮不可见且操作接口无权限。
- 授予员工分配角色、角色资源授权或资源关联接口后，对应弹窗可以读取当前关联并完成保存。
- 授权树中不再出现分页、树和关联 ID 等技术性权限项。
- 每个受保护接口至少关联一个有效菜单或操作资源，不存在遗漏接口。
- 完整初始化 SQL 的接口路径与全部受保护 Controller 路径一致。
- 初始化配置结构测试、后端测试和打包全部通过。
