# 权限资源初始化设计

## 1. 背景与目标

旧初始化数据把分页、树、详情和关联 ID 查询分别定义为 `ACTION`，导致角色即使拥有菜单，也可能因缺少页面基础查询接口而固定返回无权限；授权操作也可能因缺少弹窗依赖接口形成不可工作的权限组合。

本设计重新定义系统资源与接口关联，使每个可授权资源都是可工作的最小权限单元，并以完整空库初始化 SQL 作为精确配置真相源。

## 2. 范围

纳入系统接口目录、系统管理资源树、资源接口关联、默认部门和默认超级管理员初始化，以及对应结构测试。鉴权算法、Controller 路径、前端交互和已有数据库增量订正不在范围内。

## 3. 权限资源语义

- `DIRECTORY` 只组织导航层级，不关联接口。
- `MENU` 表示页面访问能力，关联页面首次打开和正常展示所需的分页、列表或树等基础读取接口。
- `ACTION` 表示用户主动触发的独立操作，关联完成操作所需的全部查询和写入接口。
- 分页、树和关联 ID 等页面内部调用不再作为独立 `ACTION` 出现在授权树中。
- 详情查询只有在页面存在独立详情操作时才保留独立资源；否则并入需要它的操作资源。

员工分配角色同时关联角色列表、员工当前角色和保存员工角色；角色资源授权同时关联资源树、角色当前资源和保存角色资源；资源关联接口同时关联接口列表、资源当前接口和保存资源接口。

## 4. 页面能力

| 页面 | 菜单基础能力 | 独立操作 |
|---|---|---|
| 员工管理 | 员工分页 | 新增、修改、启停、删除、重置密码、分配角色 |
| 部门管理 | 部门树 | 新增、修改、启停、删除 |
| 角色管理 | 角色分页 | 新增、修改、启停、删除、资源授权 |
| 资源管理 | 资源树 | 新增、修改、启停、删除、关联接口 |
| 接口管理 | 接口分页 | 查看详情、启停 |
| 任务管理 | 任务列表 | 执行任务 |

## 5. 初始化策略

空库依次人工执行：

1. `backend/sql/2026072201-system-init.sql`
2. `backend/sql/2026073101-permission-cache-redesign.sql`
3. `backend/sql/2026080301-system-data-reinit.sql`

使用新完整基线时不执行 `2026073001-system-data-init.sql` 和 `2026073102-task-management.sql`。SQL 可重复执行且不重复新增数据，但不负责清理或迁移已有业务数据。

## 6. 验收标准

- 普通角色只授予菜单后，页面可以正常打开并加载基础数据。
- 未授予操作资源时，对应按钮不可见且操作接口无权限。
- 授予复合授权操作后，弹窗可以读取当前关联并完成保存。
- 授权树不再出现分页、树和关联 ID 等技术性权限项。
- 36 个受保护接口与完整初始化 SQL 精确一致，且每个接口至少关联一个有效资源。

精确接口、资源及关联配置以 `backend/sql/2026080301-system-data-reinit.sql` 为准；长期工程约束以 `docs/superpowers/specs/2026-07-21-java-admin-system-design.md` 为准。
