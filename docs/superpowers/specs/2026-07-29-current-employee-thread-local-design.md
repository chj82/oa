# 当前登录员工 ThreadLocal 上下文设计

## 1. 目标与范围

将当前登录员工从 `HttpServletRequest` 属性迁移到普通 `ThreadLocal` 请求上下文。改造仅覆盖 Web 请求链路，Service 方法继续显式接收当前员工或员工 ID，不引入异步上下文传播。

## 2. 组件与职责

- `admin-common` 提供当前员工上下文持有器，只包含设置、获取和清理操作。
- `TokenAuthenticationFilter` 在 Token 认证和当前员工组装成功后设置上下文，在过滤器链退出时通过 `finally` 清理。
- `ResourceApiAuthorizationInterceptor`、`AuthController` 和 `EmployeeController` 从上下文读取当前员工。
- 删除不再使用的当前员工请求属性常量。

上下文使用普通 `ThreadLocal`，不使用 `InheritableThreadLocal`，不向异步任务或子线程传播。

## 3. 请求流程

1. 公开请求、预检请求及认证失败请求不设置当前员工上下文。
2. 受保护请求认证成功后，过滤器设置当前员工上下文。
3. 过滤器链内的权限拦截器和 Controller 可以读取同一个当前员工对象。
4. 无论过滤器链正常返回还是抛出异常，过滤器都清理当前线程中的上下文，避免容器线程复用导致身份串号。

## 4. 异常与边界

- 权限拦截器读取不到当前员工时仍返回 `401`，不改变现有错误码和响应结构。
- 当前员工接口和员工管理接口沿用认证过滤器保证，不额外引入空值降级。
- Redis、权限缓存、Cookie、事务和 Service 业务规则均不在本次改造范围内。

## 5. 测试与验收

- 上下文设置后可在当前线程读取，清理后为空。
- 不同线程之间的当前员工互不可见。
- 认证成功后，过滤器链内可以读取当前员工。
- 过滤器链正常结束和抛出异常后，上下文都为空。
- 权限拦截器和相关 Controller 不再依赖当前员工请求属性。
- 相关测试通过后，执行后端 `mvn test` 和 `mvn package`。
